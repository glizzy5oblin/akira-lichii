# Findings: memory dumps and malware triage (2026-11-21)

These add to `INCIDENT_REPORT.md`, which they confirm. All analysis was static; nothing was executed.

## 1. The verdict: a full remote-access trojan, not only a stealer
`charmap.exe` (running from `C:\Windows\Fonts\`, loaded in memory and deleted from disk) is a Go RAT. Its built-in web panel calls itself **"Akira Remote"** ("the Akira operator UI"). `calc.exe` is a stock cloudflared that published that panel on the internet through a Cloudflare quick tunnel (`--url http://localhost:49912`).

**The panel has no authentication.** No login code exists and no request carries credentials, so anyone with the tunnel URL had full control of the PC.

### Capabilities (from the panel source, `04_analysis/panel_source/app.js.txt`: 91 HTTP routes, 6 websockets)
| Area | Features (API routes) |
|---|---|
| Surveillance | Live screen (`/ws/stream`), hidden desktop / HVNC, webcam (`/ws/cam`), **microphone** (`/ws/audio`, `/api/audio/mic`), keylogger (`/api/keys`), clipboard history and set, screenshots |
| Control | Mouse and keyboard and Ctrl+Alt+Del (`/ws/input`, `/api/input/cad`), live terminal (`/ws/term`), open URL, power/lock, monitor switch, RDP (`/api/rdp`) |
| Theft | Passwords, cookies, autofill, history, recent docs, Wi‑Fi keys, Discord tokens with email/phone/2FA/billing (`/api/recovery/*`); **"Full grab … exfiltrating to Telegram"** (`/api/recovery/grab`) |
| Session hijack | "Hidden Browsers" (`/api/bot/*`): dumps browser cookies into a "vault" and opens invisible Chrome/Edge sessions with them on the victim PC, so logins look like the owner's |
| System | File manager (upload, download, zip, **run**, fetch-and-run), run program from memory (`/api/mem/run`), registry editor, services, scheduled tasks, startup items, Windows users (add, reset password), sessions, processes, TCP connections |
| Defense evasion | Defender features and **exclusions** (`/api/defender/*`), firewall rules and toggle (`/api/firewall/*`) |
| Monetization / abuse | Monero CPU miner with idle mode (`/api/miner/*`), SOCKS5 proxy through the victim's connection (`/api/socks5/*`) |
| Cleanup | Client restart, reboot, shutdown, **uninstall** (`/api/client/*`) |

### C2 and configuration
- HTTPS beacons to `/well-known/pki-validation/go/{boing,akgo.php,err.php,abe.a,qoing,qperl}` on six domains (see `IOCs.txt`).
- **Blockchain dead drop (observed in memory):** `eth_call` with selector `0x6d4ce63c` (`get()`) to BNB Smart Chain contract **`0xF97CB22B8dBd52790493e962d4684B3FDB08A2Be`**. The returned string (941 bytes) is an encoded config and was not decoded.
- Install ID in `%APPDATA%\t_id.txt` (base64 of an obfuscated string, not decoded); PID kept in `%APPDATA%\Microsoft\Internet Explorer\wd.pid`.

### Build and obfuscation
- Go, obfuscated with **garble**: build info wiped (Go version "unknown", no module list), pclntab magic overwritten (`0xb07cdade`), package paths randomized, and about 13,300 of 16,738 function names blanked.
- Libraries that kept their real names: `net/http`, `golang.org/x/net/websocket`, `github.com/gorilla/websocket`, `database/sql` (browser databases), `github.com/golang/snappy` (LevelDB / Local Storage), `github.com/ulikunitz/xz`, `archive/zip`, `golang.org/x/sys/windows` (registry, svc/mgr), clipboard.
- The author's code sits in scrambled packages, mainly `HMxzL1ajr` (59 functions), `A5Wg_wp2K5X9` (45), `OQTEr6yHqsO`, `F_J8wal`, `ES0vhvxkl`, `IEKodF`, `KKvqmcZw_aA6`, `OCl49EsyWNw8`.

## 2. What each memory dump contains
### `charmap.DMP` (the RAT)
- The RAT program, recoverable in full (19,333,120 bytes): code, embedded panel HTML/CSS/JS, C2 lists and the blockchain reply.
- **No stolen secrets were found in memory.** A masked scan for tokens, API keys, passwords, cookies, private keys, emails and seed phrases found only the program's own strings. The keylogger buffer held only the default UI text.
- It does contain the Windows username, the `PATH` (folder and project names) and the list of browsers and wallets it targets. **Keep it private.**
- The "hidden 32-bit PE" at `0x2087f950000` is a **harmless** resource-only Windows message-table DLL with no code.

### `calc.DMP` (cloudflared)
- Stock cloudflared (Go 1.27.4) run as `tunnel --url http://localhost:49912`.
- The surviving log covers only **23:40 11/20 → 00:15 11/21 CST**: edge dial timeouts from 23:56, then "**Unauthorized: Tunnel not found**" from 00:13 to 00:15. The quick tunnel was already deleted on Cloudflare's side.
- No proxied requests survive in memory. Activity before 23:40, including the previous two weeks, **cannot be reconstructed** from this dump.
- The embedded EC private key is cloudflared's own built-in key, not the user's. The two hidden images are harmless Windows message DLLs (mswsock, crypt32).

## 3. Corroboration on the host
- **Defender:** no malware-made config changes and no exclusions (5007 events are routine; the user enabled cloud protection and tamper protection at 23:39). No detections.
- **No new local users.** Services installed since 11/05 are all known vendors. BITS jobs are Google/Microsoft only. Hosts file and proxy are clean.
- So the "add exclusion" and "add user" features were not used, or not left in place.

## 4. Unknowns
- What the operator actually did through the panel during the 14 days: not recoverable from these dumps.
- Cookie vault and keylog: **most likely RAM-only** (see section 5), so there's probably no on-disk record of what was taken.
- What served `localhost:49912`: nothing was listening at collection time.
- The decoded blockchain config, and the `t_id.txt` encoding.
- Hermes Agent being present again (most likely a reinstall by the owner; confirm).
- DS4Windows from `github.com/ds4windowsapp` (not the infection vector; never ran; delete).

## 5. Where the RAT keeps data: decompiled-code results (Ghidra, 758 functions)
Searched: every decompiled function that creates or writes files (14 of them), every file path in the RAT's live memory (Go keeps an open file's full path in memory), and the panel source.

**What it writes to disk**
| Function | What it does |
|---|---|
| `0x14061e4a0` (package `AqAnF_gC`) | `%APPDATA%` (constant decoded) → `Microsoft\Internet Explorer\` → `wd.pid` |
| `AqAnF_gC.Ja1omU` | Takes the current Windows user, then writes a small file (0644). Most likely `t_id.txt` |
| `AqAnF_gC.KpajF9` | **HTTP download → file on disk**. Used for payloads from C2 (e.g. `abe.a`, miner) |
| `HMxzL1ajr.PE2ZKozh6R7d`, `.Ya67e0`, `.BNiZvC0I_t9` | `os.MkdirTemp` with pattern **`akdb*`** in `%TEMP%`: staging copies of locked browser databases (plus `-wal`/`-shm`) |
| `HMxzL1ajr.PgQmfsM1t_` | Creates a private folder (0700) and runs the **"ABE dumper"**. Decrypted error string: `GrabPasswordsOnly: ABE dumper execution failed`. That's a Chrome **App-Bound Encryption** bypass, downloaded as C2 file `abe.a` |
| `sOj41o.I3jQzl2W` | Unzip routine (zip → folders → files), for unpacking downloaded payloads |
| `F_J8wal.DiLDNQ` | `os.CreateTemp` + write: a temporary file |
| Panel "Fetch & Run" | Saves to **`C:\Users\Public\Downloads\<name>`** by default |
| Panel "Run to Memory" | Injects an uploaded program into a hollowed **`C:\Windows\System32\dllhost.exe`** by default (no file on disk) |

**The cookie vault and keylog: probably in memory only.**
- None of the file writers belongs to the panel or keylogger code.
- No vault or keylog file path is present in the RAT's memory, which would be there if such a file were open.
- The keylogger buffer was empty.

This is an inference. It means **there's probably no file on disk recording what was taken**; that history lived in RAM and on the attacker's side, including the Telegram exfil. Run `DESKTOP_PREWIPE_CHECK.ps1.txt` on the desktop to confirm and to find any staged payloads (`akdb*`, `abe*`, `Public\Downloads`).

**Other new capabilities found**
- Reads **Windows Credential Manager** (`vaultcli.dll`: `VaultEnumerateItems` / `VaultGetItem`). Count saved Windows/web credentials as stolen.
- Document grabbing (`.doc .xls .rtf .csv .jpg .png`), Jaxx wallet, card fields (`cvc2`/`cvv2`).
- Startup routine reads `--wd` / `--id` arguments and branches on mode codes `13`, `25` and `32`. `t_id.txt` starts with `25`.

**Host check:** every `dllhost.exe` running at collection was a normal COM surrogate started by `svchost`. The RAT and loader had no unexpected child processes, so there was no "Run to Memory" injection during the last session.

**Obfuscation note:** string literals are encrypted inline (garble `-literals`) and only decrypted at runtime. One was decrypted offline by hand (`04_analysis/tools/decode_literal_PgQmfsM1t.py`). Decrypting all of them (C2 URLs, every path) would need a dedicated deobfuscator.

## 6. Same malware elsewhere: Joe Sandbox report on `vscode-bootstrap.cmd` (2026-11-12)
Saved in `04_analysis/related_sample_joesandbox/`; values checked against the report's own text.
- **Same family and operator.** The report contains this incident's `exec.py` hash exactly (`fe675305…`). It also has the same contract `0xF97CB22B…` with `get()` (`0x6d4ce63c`), the same "Microsoft Display Driver Manager" → `Python399\pythonw.exe exec.py` Run value, five of the same `/go/boing` domains, the "Akira Remote" panel with passphrase `akira-mem-exec-v1`, and cloudflared to a local port (49705).
- **Different lure.** A fake VS Code bootstrap installs Node.js in `%USERPROFILE%\.vscode\nodejs` and runs a VM-obfuscated `.mjs` from `realmadridistats.org`. Its `win=25....<base64>` config has the same format as this incident's `t_id.txt`, so `t_id.txt` is very likely that encoded config.
- **Behaviour seen there:** the Go RAT injected code into `charmap.exe` and `cmd.exe`, then into **Chrome and Edge** (most likely how the ABE dumper beats Chrome's encryption; the sandbox tag is "chromElevator"). It also had a low-level keyboard hook, uploaded `DESKTOP-<host>_<user>.zip` to **GoFile**, and downloaded ffmpeg into `remotevnc\`.
- **In this incident:** none of GoFile, `VICTIM-PC_*.zip`, `REALTEKAUDIO`, `remotevnc` or the Node.js lure appears in the dumps or host evidence. The dumps only cover the last session, so earlier uploads aren't ruled out.
- **Version difference:** this panel's "Run to Memory" defaults to `dllhost.exe` and warns against `notepad.exe`; the sandbox's defaults to `notepad.exe`. This is probably a newer build of the same tool.

## 7. Automated string decryption (attempted 2026-11-21)
Mandiant's GoStringUngarbler (Unicorn emulation of the decryption routines only; calls skipped, nothing run natively) was run by the user on the rebuilt image. It recognised only 8 routines and decrypted 3 trivial strings; nothing useful was saved. The cause: this build decrypts most literals **inline** inside the functions that use them, which the tool's Go 1.21–1.23 patterns don't match. **In progress (paused):** a custom Unicorn emulator that records the buffers passed to the string-building routine, tested against the known ABE string: `04_analysis/tools/emulate_strings.py`, work files in `07_work_in_progress/string_emulator/`. Its self-test fails so far because the compiler places the key-building half of each block out of line and jumps back into the decrypt loop. The fix is to follow that jump to find the real start.
