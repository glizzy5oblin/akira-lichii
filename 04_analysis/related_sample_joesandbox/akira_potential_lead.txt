AI Summary

Final Analysis: VS Code-Themed Bootstrap and Go Payload

Executive Summary

The submitted vscode-bootstrap.cmd is a malicious bootstrapper, not a VS Code editor installer. It obtains a genuine Node.js runtime, installs native-loading dependencies, and runs an obfuscated JavaScript stage; the requested Go payload separately demonstrates process injection, keyboard hooking, browser-profile access, and persistent startup registration. Its reconstructed image also contains an extensive “Akira Remote” control interface, although not every advertised feature was verified in the Go backend. The malicious verdict is well supported, but reverse-engineering coverage remains partial .

2. Delivery Chain and VS Code Impersonation

Inspected CMD behavior

The executable CMD body:

Checks for an existing Node.js installation.

Otherwise downloads or extracts Node.js from nodejs.org , using %USERPROFILE%\.vscode\nodejs as its installation directory.

Downloads a temporary .mjs script from realmadridistats.org .

Installs koffi and lzma-native with npm.

Hides several artifacts using attrib +h , executes the JavaScript with Node.js, and deletes the temporary script.

The body ends with the success message [SUCCESS] Script completed. and exit /b . No VS Code editor installation command occurs in that inspected body. The .vscode directory is being used as a location for the Node runtime, not as proof that VS Code is installed.

Sources: vscode-bootstrap.cmd , setup variables and executable body through exit /b ; dependency command containing koffi lzma-native .

Obfuscated JavaScript stage

The certificate-style trailer decoded to a 23,127-byte JavaScript file , byte-identical to the downloaded stage recovered from the parent sandbox run. Data-only decoding recovered:

10,107 bytes of VM bytecode.

A 3,332-byte pool containing 179 strings .

Imports for koffi and lzma-native .

Native API names including VirtualAlloc , VirtualProtect , CreateThread , GetProcAddress , RtlAddFunctionTable , AmsiScanBuffer , and AmsiScanString .

These findings support a VM-obfuscated native-loading stage. The exact AMSI patching and complete manual-loader control flow were not fully verified .

A live boing response was successfully decoded by character shift, Base64 decoding, and LZMA decompression. Its resulting hash differed from the requested Go target, so the historical end-to-end delivery of that exact original Go file was not independently reproduced.

3. Go Payload: Static Inspection and Observed Behavior

3.1 Static reconstruction

The recovered Windows Go image had an entry-point RVA of 0x70500 and an image size of 0x11e6000 . Reconstruction and rebasing enabled a saved function index covering 16,254 functions and 794 source-file entries , together with annotated assembly.

A nonstandard Go metadata header was located at file offset 0xcd96c0 . Many application names were blank or mangled, complicating analysis. Ghidra failed to initialize on the reconstructed Go images; saved assembly and embedded assets remained available for targeted inspection.

The reconstructed PE retains runtime state and is not a hash-identical replacement for the original disk file .

3.2 Process injection — observed

Primary indicators from Joe Sandbox 2004448/run 0 record:

The Go process writing PE data beginning with 4D5A into cmd.exe and charmap.exe , at base 0x140000000 .

The injected cmd.exe writing PE data into Chrome at 0x12CC98F0000 .

That process creating remote threads in Chrome and Edge .

Changed thread contexts in the injected processes.

These are direct runtime indicators, not conclusions drawn solely from an automated summary or family signature.

3.3 Keyboard and browser collection — observed, with limits

The main process installed a global low-level keyboard hook. The relevant sandbox indicator reads:

0 keyboard low level NULL

It also opened a Firefox profile and files including containers.json and search.json.mozlz4 .

This establishes hooking and browser-profile access. It does not establish which keystrokes were retained, that browser passwords were successfully decrypted, or that those credentials were transmitted. The precise browser-decryption and injected-component workflow remains unresolved.

Source: Joe Sandbox 2004448/run 0 , hook, foreign-memory, remote-thread, and browser-file-open indicators.

6. Infrastructure, Configuration, and Data Transfer

6.1 Blockchain-backed staging

Target-run memory contained an eth_call request with:

{ "data" : "0x6d4ce63c" , "to" : "0xF97CB22B8dBd52790493e962d4684B3FDB08A2Be" }

The accompanying ABI response decoded into seven /go/boing delivery URLs, listed below. These are staging locations , not established interactive C2 endpoints. Relevant buffers were recovered from the run, including activity associated with injected components; no single Go function was conclusively assigned ownership of the entire exchange.

The bootstrap also supplies an encoded REALTEKAUDIO value. The standalone Go run invoked echo %REALTEKAUDIO% , but recovered output retained the literal variable reference. The complete decoding scheme and behavior when configuration is absent remain unresolved.

6.2 Cloudflare tunnel

Recovered cloudflared output records a quick tunnel:

https://horse-pathology-reader-incoming.trycloudflare.com

with local target:

http://localhost:49705

The log identifies cloudflared 2026.10.7 and settings including protocol:quic . Sandbox evidence also records the cloudflared download request and network activity under calc.exe .

Combined with the same-host panel design, this strongly suggests a local control service exposed through Cloudflare. The exact panel-to-listener routing, authentication, and method of hosting the tunnel component under the observed process identity were not fully established.

The Go version printed by cloudflared belongs to that component; it does not establish the target payload’s compiler version.

6.3 GoFile and Telegram distinction

Run memory contained a GoFile upload request and a response with status:"ok" for:

Archive: DESKTOP-OYF2376_Maoga.zip

Size: 2,818 bytes

MD5: 31bf812af4289d88319b87c32f428b34

This is evidence of an upload transaction recovered from memory. The archive contents were not inspected, so it does not establish which information was transferred. A separate recovered report string listed zero browser-item counts.

The panel displays “Full grab started … exfiltrating to Telegram.” No Telegram bot token, destination chat, or successful Telegram delivery was verified. The UI message must therefore remain separate from the recovered GoFile transaction.

Sources: decoded staging artifact decoded_contract_config.json ; cloudflared stdout.25.dr ; run-0 memory region 0xC0010FC000 , response near +0xe800 and upload request near +0x14000 .

7. Key Suspicious Indicators and False Positive Analysis

The decisive indicators are the combination of:

PE injection into system and browser processes.

A global low-level keyboard hook.

Browser-profile access.

Successful persistent startup registration under a misleading driver-management name.

Hidden bootstrap artifacts and VM-obfuscated JavaScript.

An embedded remote-control interface offering collection, execution, tunneling, and security-control requests.

Node.js, npm dependencies, Cloudflare Tunnel, and FFmpeg are legitimate technologies. Their presence alone would not justify a malicious verdict. Here, the observed injection, hooking, deceptive persistence, and inspected loader behavior provide the independent basis for that verdict.

The sandbox labels EtherHiding and chromElevator are useful correlation leads. They do not replace inspection of the blockchain and browser-injection behavior, and no specific malware family is established.

10. Evidence Limitations and Unresolved Coverage

The overall assessment remains partial . Report generation does not resolve the following gaps:

Original target unavailable: The unpacked-file download failed. Static target work used a runtime reconstruction from the exact-hash run, retaining runtime state rather than original-file bytes.

Go decompilation incomplete: Ghidra failed on the reconstructed Go images. Saved assembly and recovered metadata enabled targeted work, but not a complete backend call graph.

Control interface versus implementation: Authentication, listener initialization, and the server handlers for terminal, camera/audio, SOCKS5, memory execution, fetch-and-run, and Defender controls were not fully traced. Their presence in client code is not proof of execution.

Credential theft not fully resolved: Browser-profile access and browser injection are observed; successful password decryption, captured keystrokes, clipboard theft or replacement, and transferred credential contents are not established.

Configuration incomplete: REALTEKAUDIO , its absent-value behavior, and the complete orchestration between blockchain staging and control initialization remain unresolved.

Persistence dependency incomplete: Run-key creation is confirmed, but the Cython updater’s complete retrieval and execution logic remains unresolved. Its decompilation output also contained truncated portions.

Loader coverage remains open: VM data was decoded, but exact AMSI modifications and the full native-loading sequence were not verified.

Tunnel and auxiliary components: Cloudflared logs establish tunnel creation, but exact control routing and hosting under calc.exe remain incompletely resolved. The FFmpeg-named download was inventoried, not independently assessed.

Live-stage version mismatch: The current download is a different Go binary and was not fully reversed. The reconstructed and rebased target artifacts likewise did not receive complete semantic assessment.

Transfer evidence has content limits: GoFile request/response material was recovered from memory, but archive contents and Telegram delivery were not verified. Other memory-only endpoints remain role-uncertain.

Resource and output limits: Both shell execution and artifact reading reached their 30-call limits. Several earlier outputs were truncated, limiting examination of the full submission and auxiliary material.

These limits reduce completeness and confidence in individual feature claims, but they do not negate the independently corroborated malicious behavior.

Conclusion: The evidence establishes a malicious bootstrap and an associated Go backdoor/collection payload. Injection, hooking, and persistent registration are directly corroborated; the broader remote-control feature set is substantially documented in embedded client code but remains only partially verified at the Go backend.
